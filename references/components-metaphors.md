# 组件与视觉隐喻

## 先设计世界，再挑组件

写一句 `visual_thesis`：

```text
这个故事被理解为【题材原生世界】，因为它能把【核心关系】变成【可见空间/动作】。
```

例如“把继任理解为建筑环上的席位变化”有映射；“用一个科技圆环表现公司”没有。

## 持久世界类型

| 世界 | 适用 | 常驻结构 | 主要风险 |
|---|---|---|---|
| 证据桌面 | 调查、企业史、争议 | 窗口、来源栏、卡槽、焦点区 | UI 伪元素过多 |
| 历史书页 | 年代、人物、产品谱系 | 页边、年份、照片位、引用位 | 变成手账装饰 |
| 技术观察台 | 工艺、设备、汽车 | 主对象、扫描/状态、参数槽 | 游戏 HUD 化 |
| 产品舞台 | 产品、发布、赞助 | 英雄位、属性环、对比位 | 产品跳位或被框压缩 |
| 建筑门户 | 企业人物史 | 中央窗口、关系全屏态 | 过度占据画面 |
| 胶片/剧院 | 电影、短剧、媒介史 | 轨道/舞台、片格、观众区 | 装饰遮挡素材 |
| 地图/网络 | 地理、能源、供应链 | 节点、路径、区域、图例 | 发光地图无流向 |
| 产线/桥梁 | 流程、传输、故障 | 起点、路径、工位、终点 | 隐喻与真实机制不对应 |

## 证据组件族

### 人物卡

- 功能角色优先于冗长履历。
- 肖像、姓名/角色、一个状态标签。
- 多人物使用稳定槽位和语义色。

### 文件页

- 全貌、来源、日期/页码、局部框选、摘要。
- 原文与解释层视觉分离。

### 地图

- 地理事实、节点、路径、图例、时间状态。
- 区域发光必须解释“发生了什么”，不是气氛。

### 时间轴

- 一级年份、二级事件、当前指针。
- 长片在章节边界回到时间轴，帮助回顾。

### 关系图

- 人物、机构、资产、事件各用不同节点形状或标签。
- 线条状态：实线 confirmed、虚线 inferred、淡线 unknown。
- 方向和起止必须明确。

### 数据图

- 柱/线用于趋势，单位堆叠用于数量，卡片用于单值，流向用于交换。
- 先基线、再差值、后结论。

### 产品谱系

- 统一角度、尺度和基线。
- 按年代/类别分组；数量过多则分页或滚动。

## 对象身份锁

跨镜头记录：

```yaml
object_id: hero_product
position: center_55_52
scale: 0.38_frame_width
orientation: front_left_3q
lighting: soft_top_left
current_layer: exterior
```

属性更新不得同时改变四个身份项。若必须换角度，先完成一次明确旋转或章节清场。

## 隐喻验证

选择隐喻前回答：

1. 映射对象是什么？
2. 空间位置对应什么关系？
3. 运动对应什么变化？
4. 哪个部分不能按字面理解？
5. 不看旁白，观众能否区分起点、路径和结果？

无法回答三项以上，不用该隐喻。

## 语义色

为每色写角色而非色名：

```yaml
neutral: "史料、背景、未激活结构"
actor_a: "主体 A"
actor_b: "主体 B"
evidence: "已确认重点"
risk: "冲突、阻断、警告"
active: "当前动作或数据流"
future: "尚未实现的新状态"
```

同一颜色不得同时表示风险和成功。真实实拍优先保留自然色，MG 语义色通过边框、标签和路径进入。

## 反模式

- 任何题材都用全息圆环。
- Logo 墙代替生态关系。
- 节点很多但没有分类、方向或回收。
- 爆炸图拆开后不说明部件也不回装。
- 复古纸纹覆盖技术页，或霓虹 HUD 覆盖历史证据。
