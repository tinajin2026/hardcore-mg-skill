# 注意与阅读编排

本层回答的不是“对象怎样动”，而是“观众先看什么、每拍只新增什么、什么时候开始读、读完后把注意交给谁”。方法栈决定认知任务，微运动层决定变化包络，注意与阅读层则为每镜建立可审计的焦点路径和运动预算。

## 与微运动层的边界

```text
method_stack: 这段为什么这样组织，哪些方法共同承担认知任务
micro_motion_plan: 一个变化怎样起势、发生、响应、制动和停稳
attention_reading_plan: 观众从哪里进入，按什么顺序读，每拍得到什么，何时允许阅读，焦点交给哪里
```

三层可以共同约束同一个微时间拍，但不能互相代替：

- `MM03` 约束主动作包络；`AF03` 约束该拍只新增一个可陈述的语义差异。
- `MM11` 约束动作停稳后留白；`AF08` 从画面稳定且信息完整时才启动有效阅读时钟。
- `MM05` 维持几何连续；`AF10` 维持跨镜注意连续，二者的锚可能相同，也可能分别是位置与概念。
- 没有可见运动的镜头仍必须有注意入口、焦点路径、信息增量和退出焦点；“静止”不是空白状态。

## 十二条规则

### AF01 首焦声明

- **触发**：新镜头、新主体、新论点、新证据类型或章节重置。
- **脑内画面**：画面打开的第一瞬间，只有一个对象能回答“这镜先看谁”。
- **执行**：用尺度、位置、明暗、清晰度、朝向或入场先后建立唯一 `attention_entry`；其他对象至少在一个维度退阶。
- **原理**：观众先获得观察对象，后续关系和信息才有挂载位置。
- **避免**：标题、人物、数字、图标同时以最高对比入场；把“画面中心”误当成已经建立首焦。

### AF02 信息空位预分配

- **触发**：人物、产品、实拍操作、地图、界面或证据旁边还要出现文字、数字、标签。
- **脑内画面**：信息进入前，画面里已经有一块属于它的安静区域。
- **执行**：在构图阶段锁定标题槽、证据槽、数据槽和来源槽；避开面部、手势、产品操作区、图表关键区及字幕安全边界。
- **原理**：后加信息不需要挤压主体或临时重排世界，阅读路径更稳定。
- **避免**：先把主体铺满，再用半透明底板强行覆盖；将负空间当成无意义装饰区。

### AF03 单拍单语义增量

- **触发**：列表、步骤、节点、图表、时间线、关系图、产品状态或多条证据逐步建立。
- **脑内画面**：每个微时间拍结束时，观众能用一句话说出“刚刚多知道了什么”。
- **执行**：为每拍写唯一 `information_delta`；既有结构保留，只新增一个类别、关系、差异、原因或结果。可有从属响应，但不得产生第二个独立结论。
- **原理**：语义增量和时间增量一一对应，因果、步骤与比较不会被同时更新冲淡。
- **避免**：一个拍里同时加节点、连线、标题、数字和结论；把多个装饰变化误写成信息增量。

### AF04 阅读顺序时间化

- **触发**：标题加限定词、数字加单位、比较值加基线、证据加来源、主体加关系说明。
- **脑内画面**：空间层级不只靠大小，出现顺序本身就是阅读箭头。
- **执行**：通常按 `对象/主张 -> 关键值/动作 -> 限定词/单位 -> 来源/关系` 进入；根据论证需要调整，但必须把 `focus_path` 写成有序列表。
- **原理**：把瞬时视觉竞争变为可跟随的时间序列，观众不必自行猜阅读顺序。
- **避免**：所有字段同时淡入；让来源先于主证据占据注意；数字和单位分离到无法配对。

### AF05 全景—局部证据—回装

- **触发**：文档、网页、地图、系统、机器、流程、档案或界面需要局部证明。
- **脑内画面**：先知道证据属于哪里，再看关键局部，最后把局部结论装回整体判断。
- **执行**：先给完整容器或系统，再通过裁切、框选、放大或局部高亮聚焦证据，结尾回到同一坐标或明确的系统状态。
- **原理**：局部细节保留来源和结构上下文，既可读又不被误解成孤立素材。
- **避免**：直接从无上下文的放大细节开场；看完局部后跳到无关画面，不完成回装。

### AF06 坐标容器锁

- **触发**：数据比较、同类产品、年份替换、界面步骤、图表、地图路线、前后状态或多条证据横向比较。
- **脑内画面**：世界、网格、尺度、观察角度和槽位不动，变化对象在同一把尺子上更新。
- **执行**：锁定轴、基线、视口、卡槽、对象中心和尺度；比较期间只替换值、状态或当前对象。若必须改尺度，先显式重置章节。
- **原理**：观众把注意用于差异而不是重新学习坐标，比较结论更可信。
- **避免**：每个数据点换一种图表；前后状态改变视角和大小；用运镜掩盖不可比。

### AF07 阅读负载反向运动预算

- **触发**：出现文字、数字、代码、文件、密集 UI、图表或需要辨认的证据。
- **脑内画面**：信息越密，世界越安静；高能动作只发生在不要求读取的窗口。
- **执行**：为每镜标记 `motion_budget: static | low | medium | high`。任何有文字事件的有效阅读窗口只能是 `static` 或 `low`；若需要高能进入，先完成动作，再降速进入阅读。
- **原理**：眼动追踪和符号解码共享有限注意资源，持续全画幅运动会吞掉阅读能力。
- **避免**：代码滚动时推拉摇移；数字读取期间背景粒子满屏活动；把运动强度当成信息重要性。

### AF08 稳定后启动阅读时钟

- **触发**：任何必须读懂的文字、数字、图表结论、界面状态或来源标签。
- **脑内画面**：文字入场只是准备，等字形、对象、相机和绑定关系都稳定后，阅读才真正开始。
- **执行**：`reading_lock` 写清稳定条件和有效阅读区间；入场、缩放、变形、模糊恢复与相机减速不计入阅读时长。退出只能发生在阅读责任完成之后。
- **原理**：防止形式上“出现过”但实际上没有可读时间的伪完成。
- **避免**：把 0.6 秒弹入动画算作 0.6 秒停留；文字稳定时仍让承载对象旋转或离开景深。

### AF09 单一活动强调

- **触发**：多个节点、列表项、步骤、指标、区域或同类产品同时在场。
- **脑内画面**：旧信息还在，但只有当前解释对象发亮、变色、加粗或获得活动边框。
- **执行**：活动色或最高对比一次只给一个语义目标；已讲信息转为持久低阶，未讲信息保持预备态；切换强调时明确前一项如何退阶。
- **原理**：既保留整体结构，又把当前注意义务压缩到一个位置。
- **避免**：所有节点都闪；历史项消失导致结构丢失；用多种强调色同时表达同一种“当前”。

### AF10 焦点交棒

- **触发**：多镜段落、跨段连续、实拍与 MG 接力、总览与局部切换或证据链推进。
- **脑内画面**：本镜最后看见的对象、方向、词或关系，正是下一镜最先接住的东西。
- **执行**：为每镜写 `exit_focus`；除最后一镜外使用 AF10，并让下一镜 `attention_entry` 在对象、位置、方向、形状、颜色或概念上明确承接。必要时同时声明几何锚和语义锚。
- **原理**：切镜不迫使观众重新搜索，注意连续性成为叙事连续性的一部分。
- **避免**：上一镜结尾高亮 A，下一镜从无关角落出现 B；只写“自然过渡”而没有可观察承接物。

### AF11 证据与装饰竞争隔离

- **触发**：真实文档、网页、档案、UI、数据表、引用或来源证明与风格化背景并存。
- **脑内画面**：证据是前景可读物，装饰只证明视觉世界存在，不能冒充第二条信息。
- **执行**：证据区获得清晰度、对比和稳定性；纹理、粒子、辉光、扫描线、背景字与无关循环动画降到不影响辨认的层级。来源标签绑定证据而非漂浮在装饰层。
- **原理**：保护证明材料的权威和可读性，避免“看起来很科技”替代实际证据。
- **避免**：在正文上叠扫描噪声；装饰数字比真实数字更醒目；来源与证据空间脱钩。

### AF12 实拍主体优先权

- **触发**：人物、采访、演示、产品操作、工业过程、舞台、档案或真实环境与 MG 混合。
- **脑内画面**：MG 像一名懂分寸的编导，在真实主体旁边解释，而不是站到主体前面表演。
- **执行**：面部、眼神、手势、接触点、操作路径和产品关键结构拥有最高遮挡优先级；MG 使用侧向空位、贴附标注或短暂全屏解释，并在实拍动作发生时降低对比和运动。
- **原理**：真实动作承担存在性和因果证据，MG 负责不可见关系和阅读组织，分工清楚才可信。
- **避免**：标签遮脸遮手；操作进行时全屏 HUD 抢焦；把真实过程重画一遍却丢掉证据价值。

## 自动触发组合

规则按语义完整激活，不设数量配额。常用组合不是模板，而是最低责任提醒：

| 当前镜头义务 | 常见触发组合 | 关键结果 |
|---|---|---|
| 新主体加一句标题 | AF01 + AF02 + AF04 + AF08 | 先认主体，再读标题，动画不吞阅读时间 |
| 数据比较 | AF03 + AF04 + AF06 + AF07 + AF09 | 同一基线逐项更新，只突出当前差异 |
| 文档或网页证据 | AF02 + AF05 + AF07 + AF08 + AF11 | 有来源上下文、局部可辨、装饰退阶 |
| 流程或机制 | AF03 + AF05 + AF06 + AF09 + AF10 | 一步一增量，机制回装，焦点连续 |
| 实拍加解释层 | AF02 + AF07 + AF11 + AF12 | 主体不被遮挡，解释与真实动作分时 |
| 多镜头论证链 | AF01 + AF04 + AF05 + AF10 | 每镜首焦明确，证据和结论能接力 |
| 高能标题入场后阅读 | AF01 + AF04 + AF07 + AF08 | 高能只负责进入，减速后另算阅读 |

冲突优先级：

1. 可辨认的真实主体与真实证据优先于装饰和氛围。
2. 阅读义务优先于持续运动；不能同时成立时分成动作窗口与阅读窗口。
3. 同基线比较优先于镜头炫技；需要重置坐标时必须显式结束上一比较。
4. 一个时间点只能有一个首焦和一个活动强调；多个方法可以共同服务它。

## 逐镜执行合同

每段写 `attention_reading_plan.shot_bindings`，每镜恰好一条：

```json
{
  "shot_id": "Shot 1",
  "rule_ids": ["AF01", "AF02", "AF04", "AF08", "AF10"],
  "attention_entry": "先看中央产品轮廓",
  "focus_path": ["产品轮廓", "右侧主指标", "指标单位与限定词"],
  "information_delta": "建立产品与主指标的唯一对应关系",
  "motion_budget": "low",
  "reading_lock": "产品和相机停稳后，主指标保持完整可读至切镜",
  "exit_focus": "右侧主指标终点，下一镜从同坐标接住"
}
```

合同门禁：

- 每个镜头恰好出现一次，`rule_ids` 只能为 AF01–AF12 且不重复。
- `focus_path` 按实际观看顺序书写，不用“从左到右”替代对象名称。
- 每镜只声明一个可复述的 `information_delta`，但可由多个微拍共同完成。
- 有 `text_events` 的镜头必须使用 AF04、AF07 或 AF08 中至少一条，且 `motion_budget` 只能是 `static` 或 `low`。
- 多镜段落中，除最后一镜外都必须使用 AF10；`exit_focus` 必须写出下一镜能接住的对象、位置、方向或概念。
- `reading_lock` 即使没有文字也不能省略：应说明无需阅读，还是需要识别对象、关系或结果。
- AF ID 只留在 JSON 审计层；H3 Prompt 写具体焦点、顺序、减速、停稳和交接，不输出规则编号。

## 导演自检

逐镜用七问收口：

1. 第一眼看谁，画面中是否存在第二个同强度候选？
2. 焦点经过哪些对象，顺序是否由时间和构图共同支持？
3. 这一拍只新增哪一个可陈述信息？
4. 文字或证据稳定后，实际可读多久？
5. 当前运动预算与阅读负载是否相容？
6. 装饰、实拍和证据谁拥有最高注意权，理由是什么？
7. 本镜最后把焦点交给下一镜的哪个可观察锚？
