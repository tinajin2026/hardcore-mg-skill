# 审核友好编译与差量修订

## 两阶段 Prompt

### 导演版

完整写出：空间、对象、信息、动作、时间、实拍处理、连续性、文字和失败风险。导演版是思考真源，不直接追求短。

### 执行版

按以下优先级压缩：

1. 保留技术规格、核心判断和媒介模式。
2. 保留对象身份、空间坐标和状态顺序。
3. 保留时间拍、文字内容、数据单位和段尾接口。
4. 合并同义形容词。
5. 删除无语义氛围词、重复禁令和低价值材质堆叠。
6. 将现实人物/品牌按实体策略中性化。
7. 只保留 3–6 条最可能失败的负向约束。

## 实体策略

- `neutralize`：默认。人物改功能角色，品牌改原创标识/中性产品，地点改抽象地图。
- `hybrid`：保留对叙事不可替代的低风险文字，其余视觉主体中性化。
- `preserve`：用户明确要求，且素材权利和目标模型允许。

中性化只改视觉身份，不改原稿中的核心论点、时间和因果。

## Prompt 中的负向约束

不要在每段复制长黑名单。只列本段会高概率发生的错误，例如：

- 文件页：不要生成不可读伪文字，不要裁掉来源。
- 产品：不要改变产品数量、颜色和朝向。
- 关系图：不要添加未给出的节点或关系。
- 实拍 HUD：不要遮挡脸、手、道路和产品轮廓。
- 竖屏：不要拉伸，不要把底部安全区变成字幕带。

## 生成前自动检查

运行 `scripts/validate_output.py` 检查结构字段、跨段接口和禁止的字幕/旁白指令。自动检查只能抓合同错误，不能替代视觉验收。

## 逐帧验收

### 构图

- 第一焦点是否在 0.5–1 秒内成立。
- 关键对象是否完整、比例合理、不被边框压缩。
- 文字、数据和 UI 是否互不遮挡。

### 叙事

- 每段唯一核心判断是否真的可见。
- 实拍和 MG 是否承担不同职责。
- 因果、机制和数据是否按正确顺序出现。

### 连续性

- 对象位置、尺度、朝向和光源是否继承。
- 语义色是否保持含义。
- 上段段尾与下段首帧是否对应。

### 文本

- 没有底部口播字幕或旁白全文。
- 章节、证据、数据、UI 的角色可区分。
- 文件和数据有来源、单位或时间尺度。

### 运动

- 同一时刻只有一个高能动作。
- 高密度信息有稳定停留。
- 转场与章节/对象有语义关系。

## 差量修订

失败后不要整体重写。记录：

```yaml
preserve:
  - 已成功的对象、布局、色彩、节奏
fix:
  - 可观察失败与时间范围
patch:
  - 最小状态/动作/文字修改
acceptance:
  - 修订后可观察条件
```

优先修根因：对象漂移通常是身份锁缺失，不是“稳定性不够”；信息太乱通常是并发焦点过多，不是“动画不够高级”。

## 不可由静帧证明的内容

缓动曲线、音画同步、精确帧长、微妙相机运动和声音设计必须通过视频播放或时间线证据确认。只有联系表时写 `unverified`，不要补想象。
