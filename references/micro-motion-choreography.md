# 微运动编排法

这套规则解决的不是“用什么转场”，而是一个动作怎样起、谁先动、谁后响应、哪里保留、何时真正停稳。它来自 43 条成片的第三遍高时间分辨率审看：每片从六个全时域区域抽取一个强变化窗口，合计 258 个 1.2 秒窗口、3096 帧。运行时只使用去来源化的决策规则，不回查片名、时间码或原构图。

## 自动编排顺序

对每镜依次回答，不设动作条数配额：

```text
语义变化有多大？
-> 哪个对象必须保持身份或位置？
-> 观众应先看到哪一个变化？
-> 哪些层只能作为延迟响应？
-> 动作如何制动？
-> 结果需要保持多久才能读懂？
```

先决定 `change_scope`：

- `local`：一个节点、标签、按钮、数值或部件改变，禁止全屏洗掉其他信息。
- `regional`：一个面板、卡槽、前景层或画面区域改变，保留世界与其余证据。
- `full_frame`：章节、年代、地点、论证层级或视觉世界整体重置，才允许全画幅清场。

再把每镜写成 `attention cue -> anticipation -> primary change -> delayed response -> settle -> readable hold`。不存在的环节写明为何省略，不能用多个同时启动的动作蒙混过去。

## 十二条微运动规则

### MM01 注意先行

**触发**：主体将移动、替换、展开或被证据指认。  
**脑内画面**：先有光标、描边、局部亮度、视线、短标签或构图空位把注意力引到动作起点，随后主体才改变。  
**执行**：提示只领先一个短拍，强度低于主动作；提示一旦完成使命就减弱或并入结果。  
**原理**：观众先知道看哪里，才能把随后的位移理解为信息而非噪声。  
**禁止**：提示与主体同时爆发；用无指向闪光代替注意线索。

### MM02 主体先动，依赖层后响应

**触发**：连线、标签、阴影、粒子、数字、框线或声效依赖某个主体状态。  
**脑内画面**：节点先落位，连线再生长；产品先展开，标签再吸附；按钮先被触发，结果状态再出现。  
**执行**：主对象拥有唯一高能动作；依赖层延迟一个可感知短拍，按因果顺序逐层响应。  
**原理**：时间顺序就是因果解释。  
**禁止**：所有图层同帧弹出；装饰层抢在原因之前运动。

### MM03 起势—主变—制动—停稳

**触发**：任何可见位移、缩放、旋转、揭示、变形或清场。  
**脑内画面**：对象先蓄势或从静止脱离，经过单一主变化，在目标位置明显减速并停稳。  
**执行**：为主动作写清 `from_state`、峰值、`to_state` 与 `settle`；不要求每步占固定时长，但不能把匀速漂移当完成。  
**原理**：制动让观众确认状态已经改变，也给下一拍提供确定起点。  
**禁止**：无起点的突然滑动；抵达后继续呼吸、抖动或漂浮。

### MM04 中性场清句

**触发**：章节、年代、地点、证据类型或视觉世界发生真正重置。  
**脑内画面**：旧信息先退入短暂的黑、白、品牌色或低信息场，新章节从干净状态建立。  
**执行**：中性场是短标点，不是装饰闪白；旧信息先完成退出，新信息随后进入，必要时保留一个连续锚。  
**原理**：认知重置需要清空工作记忆，短暂低信息场能阻止两章互相污染。  
**禁止**：每次切镜都闪白；旧新内容在高亮场中叠成不可读混合物。

### MM05 连续锚先留后换

**触发**：对象身份、产品角度、窗口、纸张、世界框架或空间轴线需要跨状态延续。  
**脑内画面**：保留一个位置、轮廓、边缘、窗口或运动方向，其余层在它周围替换，最后锚点成为新状态的一部分。  
**执行**：明确锚点的几何、坐标、尺度和光源；先锁锚，再替换背景/信息/材质。  
**原理**：变化只有依附于不变量才可被比较。  
**禁止**：全画面同时变形；“形态匹配”却改变中心、朝向和尺度。

### MM06 变化范围服从语义范围

**触发**：任何更新、替换、强调或转场。  
**脑内画面**：局部事实只在局部改，区域模块在区域内换，只有全局论证重置才清全屏。  
**执行**：把 `local | regional | full_frame` 写入实现；遮罩、擦除、光扫和推拉不得越过该范围。  
**原理**：视觉变化面积暗示语义变化幅度；范围失配会夸大或削弱信息。  
**禁止**：改一个数字却全屏爆炸；换章节只改一个角标而无结构信号。

### MM07 前后景接力

**触发**：实拍与 MG、纸张与档案、产品与背景、舞台与屏幕等存在深度层。  
**脑内画面**：前景对象先遮挡或穿越，中后景在遮挡期间替换，前景退出后显露新世界。  
**执行**：一次只让一个深度层承担主位移；遮挡边缘、运动方向和景深连续，背景不与前景对冲。  
**原理**：真实遮挡提供天然切点，能让媒介转换保持空间可信度。  
**禁止**：前景、背景和相机三者同时高速运动；无实体依据的任意蒙版。

### MM08 领域对象承担转场

**触发**：题材里存在可运动的原生对象、结构或操作。  
**脑内画面**：车轮/车身切线、纸页、屏幕窗口、扫描线、时间轴、胶片门、光束、机械部件或数据路径完成换场。  
**执行**：载体必须先属于当前世界，再用它的真实方向、结构或功能清场，并在新状态留下结果或余韵。  
**原理**：领域原生运动同时完成叙事、风格与连续性，不需要外挂特效。  
**禁止**：找不到语义理由仍套故障、粒子、液体或镜头光晕。

### MM09 容器先立，信息后填

**触发**：标题、图表、UI、证据卡、年表、节点图或参数标签进入。  
**脑内画面**：先建立窗口、坐标、卡槽、标题基线或图表骨架，再逐项填入文字、数值、节点和关系。  
**执行**：容器/几何是前置主动作；内容按阅读顺序进入，复杂文字在运动结束后才开始计阅读停留。  
**原理**：稳定框架减少每条新信息都重新定位的成本。  
**禁止**：框、字、数字和图标同帧弹出；文字边移动边要求阅读。

### MM10 同槽替换与几何匹配

**触发**：前后状态可比较，或同类产品、年代、方案、页面、数值需要逐项替换。  
**脑内画面**：旧对象在固定槽位退场，新对象从同一中心、基线、轮廓或轴线接替。  
**执行**：锁定比较坐标；旧项退出和新项进入可交叠但不得同时抢焦点，匹配完成后再显示差异标签。  
**原理**：位置不变把注意力从“找对象”转移到“看差异”。  
**禁止**：每项随机飞到不同位置；用复杂变形掩盖不可比关系。

### MM11 动后必读

**触发**：动作产出结论、产品状态、证据、标题、数值或可继续接力的段尾状态。  
**脑内画面**：运动能量收完，相机和主体共同安静，结果保持到观众完成一次识别或阅读。  
**执行**：停留长度由阅读量和复杂度决定，不设统一秒数；停留从文字/结果完全稳定后开始，而非从进入动画开始。  
**原理**：运动制造注意，静止完成理解。  
**禁止**：结果一出现立刻切走；用持续浮动假装画面“有生命力”。

### MM12 持久世界只动增量

**触发**：多拍解释、系列页面、品牌章节、技术世界或长段需要保持同一语境。  
**脑内画面**：框架、网格、舞台、品牌色、窗口或光源持续存在，每一拍只更新一个增量。  
**执行**：先列不变量，再定义本拍唯一 `delta`；未被当前语义触发的层保持静止。  
**原理**：稳定背景把运动预算留给真正的新信息，并强化同一世界的累积感。  
**禁止**：每拍重建全套背景；所有层为了“高级感”持续缓动。

## 自动触发表

| 稿件或画面条件 | 必选/优先规则 | 组合结果 |
|---|---|---|
| 动作有原因与结果 | MM02 + MM03 + MM11 | 原因先发生，反馈后到，结果停稳 |
| UI、图表、证据卡、节点图 | MM09 + MM02 + MM11 + MM12 | 先建框架，逐项填入，在稳定世界中读结果 |
| 年代、方案、产品或数值比较 | MM05 + MM10 + MM11 | 同一坐标替换，差异可直接比较 |
| 章节/地点/年代整体切换 | MM04 + MM05 + MM06 | 全局清句但保留一个连续锚 |
| 实拍进入 MG 或 MG 回到实拍 | MM05 + MM07 + MM08 | 由真实前景/领域对象接力，不靠任意遮罩 |
| 产品、机械、交通、胶片、屏幕题材 | MM08 + MM03 + MM05 | 原生结构承担运动，身份不漂移 |
| 只改一个标签、数字或部件 | MM06 + MM12 + MM11 | 局部更新，其余世界静止，改完可读 |
| 高信息密度 | MM01 + MM09 + MM11 + MM12 | 先定注意和容器，降低并发运动 |

## 组合规则

1. `MM03` 是所有可见主动作的默认包络；它不是额外动作。
2. `MM02`、`MM09` 和 `MM11` 常组合成 `框架建立 -> 内容填入 -> 结果停留`。
3. `MM04` 只能在 `full_frame` 语义重置时使用；局部更新优先 `MM06` 或 `MM10`。
4. `MM05` 决定保留什么，`MM06` 决定改多大，`MM08` 决定由什么完成改变，三者职责不可互相替代。
5. `MM07` 发生时，相机通常降级为固定或低幅跟随，避免三重运动竞争。
6. 多条规则可以约束同一个微时间拍，不因此增加可见动作数量；不可为了覆盖规则而塞入无语义动作。

## H3 落地合同

每段在 `micro_motion_plan.rule_bindings` 中写实际启用的规则。每条 binding 必须说明：

```text
rule_id + triggered_by + applies_to_shots
+ implementation + failure_prevented
```

每镜至少被一条 binding 覆盖；所有可见主动作必须由 `MM03` 覆盖；含文字事件的镜头还必须由 `MM09` 或 `MM11` 覆盖。`implementation` 必须指向当前对象、范围、顺序和落点，不能只复述规则名。

随后把规则真正写进已有字段：

- `primary_action`：对象、起止状态、目的和制动。
- `micro_beats`：唯一主变化、延迟响应与停稳。
- `layers`：哪些层保持，哪些层只承担响应或清场。
- `entry_state/delta/exit_state/handoff`：不变量、唯一增量与可接续落点。
- `text_events`：进入结束、稳定阅读和退出责任。
- `camera`：与对象运动分工，不能互相抵消。

规则 ID 进入 JSON 只为可审计，不写进 H3 原生 Prompt。Prompt 只保留对象、动作顺序、因果延迟、变化范围、连续锚和稳定落点。
