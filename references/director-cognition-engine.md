# 编导脑内画面引擎

## 目标

这套引擎模拟的不是“给句子配一个画面”，而是编导面对一段文稿时的连续判断：这句话要观众理解或相信什么，哪一种证据能承担它，脑中应先出现什么空间关系，画面如何变化，最后停在哪个可继承状态。

固定链路：

```text
文稿刺激
→ 核心判断
→ 证据责任
→ 脑内画面候选
→ 淘汰陈词滥调与伪证据
→ 选择视觉世界和对象
→ 编排信息顺序与主动作
→ 设计实拍/MG接力
→ 固化段尾状态
→ 渲染后用证据复核
```

任何一步缺失，都容易退化为“看到 AI 就画芯片，看到增长就画箭头”的关键词配图。

## 一、先把帖子读成导演问题

每个语义单元只回答六个问题：

1. `claim`：这一段唯一要成立的判断是什么？
2. `trigger`：是哪一个词、数字、关系或转折触发视觉化？
3. `evidence_need`：需要证明真实存在，还是解释不可见关系？
4. `audience_question`：观众此刻最可能问“谁、何时、多少、为什么、怎么运作、然后呢”中的哪一个？
5. `end_state`：这一段结束时，观众脑中必须留下哪个对象和哪个状态？
6. `uncertainty`：哪些事实、关系、单位或来源尚未确认？

如果一段同时有两个核心判断，先拆段。若无法写出 `end_state`，说明脑内画面还没有闭合。

## 二、强制生成三种脑内候选

不要接受第一个联想。对每个单元至少生成三种功能不同的候选：

| 候选 | 首先寻找什么 | 适合什么 |
|---|---|---|
| 证据原生 | 文件、帖子、真实UI、产品、现场、地图、原始数据 | 证明“它确实存在/发生” |
| 机制原生 | 剖面、路径、节点、比较台、状态机、因果链 | 解释“它为什么、怎么运作” |
| 领域原生 | 该题材自己的对象、空间和动作语汇 | 建立记忆点和章节世界 |

用以下问题淘汰候选：

- 删掉旁白后，画面仍表达同一个关系吗？
- 这个对象和题材有真实结构关系，还是只因为“看起来高级”？
- 画面是否暗示了文稿没有支持的新事实？
- 能否用一个主动作完成，而不是五个装饰动作？
- 结尾能否成为下一镜的明确输入？
- 在实际画幅和停留时间内能读完吗？

默认选择信息增益最高、事实风险最低、连续性成本最小的候选。两个候选各自承担不同责任时才允许组合，例如“实拍证明产品存在 + MG解释内部机制”。

## 三、从刺激反推脑内画面

| 文稿刺激 | 编导先想到 | 画面落法 | 首选动作 |
|---|---|---|---|
| 一条帖子或引用 | 原始载体、出处和被圈出的关键句 | 全貌→局部框选→回到全貌 | `N06 E01 T05` |
| 一个大数字 | 基线、单位和空间尺度 | 基线→差值→结论 | `N07 T04 E05` |
| 两个主体竞争 | 同尺度双边舞台 | 同坐标逐项替换 | `N02 C05 K01` |
| “因为…所以…” | 有方向的三段链 | 原因→传输→结果，保留已成立节点 | `N04 E04 M05` |
| 看不见的内部机制 | 同一对象的外观与剖面 | 整体→拆解→路径→回装 | `N05 M07 H04` |
| 多年历史 | 可定位的时间坐标 | 年份锚点、阶段卡、产品或人物谱系 | `N03 E06 X07` |
| 产品能力 | 产品英雄位与使用结果 | 实物→机制/参数→真实使用 | `W04 C01 H04` |
| 人物、组织、资金关系 | 可增量生长的证据网 | 功能人物卡、方向线、确定性状态 | `R04 E02 E03` |
| 多种异质素材 | 稳定窗口或工作台 | 外框不动，只更新内容槽 | `R07 C02 X04` |
| 重大转折 | 旧世界收束、新世界开门 | 清场、章节卡、材质换挡 | `N08 T01 K07` |
| 第一视角或运动实拍 | 干净现实与后加感知层 | 干净实拍→跟踪HUD→必要时关闭 | `R06 H02 H08` |
| 抽象能力、压力、阻力 | 可被推动、阻挡、装载或拆开的实体 | 选择一个与论点同构的物体并改变状态 | `N01 W07 M08` |

完整动作定义见 [director-move-catalog.yaml](director-move-catalog.yaml)。不要把 ID 原样堆进 Prompt；先把它们实例化为当前对象、位置、动作和证据。

## 四、自动激活多维方法栈

一段稿件通常不是只触发一条方法。先用 [method-trigger-lattice.yaml](method-trigger-lattice.yaml) 判断一个主语义信号和零到四个次信号，再用 [method-composition-engine.md](method-composition-engine.md) 选择一个主结构程序和零到三个辅助程序。最后把当前题材特征交给 [director-method-recipes.json](director-method-recipes.json) 与 `scripts/compose_method_stack.py`，得到一个主执行配方、零到两个叠加配方和已经消解冲突的动作候选。

四层职责不可混淆：

```text
语义信号 SG：这段要求观众完成什么认知运算
结构程序 DP：opening 到 landing 的状态骨架怎么走
执行配方 DR：证据、媒介、世界和题材对象如何落地
原子动作 N/R/W/C/T/E/K/M/X/H/L/Q：每个对象具体承担什么变化
```

组合不是把效果叠在一起，而是让方法分工：主程序决定骨架，叠加配方只补证据、比较、文字、媒介接力、连续性或落点。一个持久世界只能有一个；同一微时间拍只能有一个主动作；真实证据与解释性重建冲突时真实证据优先；高密度机制/数据与高能运镜冲突时稳定阅读优先。

确定性预编译示例：

```bash
python3 scripts/compose_method_stack.py \
  --features QUOTE,DATA,RELATION,INVESTIGATION \
  --primary QUOTE
```

脚本输出主配方、叠加配方、世界锁、按语义完整激活的动作、冲突说明、媒介政策和失败信号。把动作逐条实例化为当前主体、坐标和状态；若因真实素材或时长约束替换动作，必须在 `collision_resolutions` 或 `discarded_methods` 里说明差量，不能悄悄改写。

## 五、编导意图台账

在写分镜和生成 Prompt 前，为每个语义段生成一条内部台账：

```yaml
source_span: 原文范围
core_claim: 唯一判断
trigger: 触发词/数字/关系/转折
audience_question: 观众此刻要解决的问题
evidence_need: existence | source | relation | mechanism | comparison | mood
candidate_images:
  - type: evidence_native
    picture: 具体脑内画面
    reject_reason: null
  - type: mechanism_native
    picture: 具体脑内画面
    reject_reason: 信息重复或证据不足
  - type: domain_native
    picture: 具体脑内画面
    reject_reason: 陈词滥调
selected_picture: 被选择的视觉世界、主体和空间关系
move_ids: [N04, E04, M05, L04]
media_responsibility: MG解释因果，实拍只证明现实结果
primary_action: 单一主动作
initial_state: 可执行初态
end_state: 可继承终态
uncertainty: 待核实的事实或关系
```

同一 H3 语义段按认知任务选择全部必要原子动作，不设数量上下限，其中必须包含 `N` 文稿触发、`C` 构图、`M` 动效、`L` 连续性和 `Q` 质量防护。其他维度没有真实触发就不选；有真实义务也不能因为数量好看而删。原子动作是方法职责，不等于逐个播放的可见事件；每条 `application` 必须写清当前镜头、对象和状态如何落地。

## 六、候选评分

每项 0–2 分，低于 8 分重想；任何事实红线命中直接淘汰。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 语义同构 | 只相关题材 | 能辅助理解 | 画面状态直接等于论点结构 |
| 证据责任 | 冒充证据 | 责任模糊 | 明确区分证明与解释 |
| 一眼焦点 | 多点争抢 | 需旁白引导 | 第一眼就是核心判断 |
| 动作必要性 | 装饰运动 | 部分有用 | 主动作推进信息状态 |
| 连续性 | 无法接镜 | 可人工补救 | 段尾天然成为下一镜初态 |
| 可生成性 | 依赖脆弱细节 | 可分层生成 | 对象、坐标、状态和顺序明确 |

事实红线：伪造来源、虚构人物或关系、无单位数据、生成画面冒充档案、不同产品假装同一对象、无法从视觉证据确认却声称精确声画同步。

## 七、一个帖子如何变成画面

示例文稿：`三年内，某方案把处理成本降到原来的五分之一，但代价是系统更依赖上游能源。`

导演拆解：

- 核心判断不是“成本下降”，而是“成本优势与能源依赖同时增加”。
- 证据候选：真实账单或报告页，能证明数字；缺来源时不得伪造。
- 机制候选：同一流程台上，成本柱下降，能源输入线变粗。
- 领域候选：把系统做成能量管线和处理节点，成本作为结果表，不用向下箭头充当全部画面。
- 选择：先用来源页确认数字，再进入稳定流程台；锁定同一系统，逐步更新成本与能源依赖，最后停在双结果状态。
- 方法组合：主程序 `DP18 价值交换双结果`，辅助 `DP13 价值成本流向`；执行配方以成本拆账为主、来源取证为叠加。
- 动作栈：`N07 E05 N04 W07 M05 M08 Q05 L02`，分别承担数字口径、因果顺序、世界、运动、连续性与事实防护。
- 拒绝：巨大的“5X”加粒子爆炸，因为它只放大数字，没有解释代价。

最终 Prompt 写具体对象和状态，不写“请使用 N07”。动作 ID 是编导检索和审计语言，不是给视频模型看的暗号。

## 八、养料蒸馏后的使用原则

运行时不回忆参考片，也不搜索题名、案例编号或原片时间码。样片已经被压成 96 条动作；新稿件只根据当前判断结构触发它们。

1. 方法的可信度来自研究阶段，当前导演板只呈现它为何被这段新原文触发。
2. 动作 ID 只是内部检索语言；画面描述必须落到当前主体、空间、状态和作用。
3. 多个方法同时触发时，先由 [method-trigger-lattice.yaml](method-trigger-lattice.yaml) 选择一个主程序，再由执行配方和辅助程序承担局部责任。
4. 每条动作都要写协作对象；无法与主骨架建立关系的动作视为装饰并删除。
5. 最终效果以 opening、development、turn、payoff、landing 的同一状态链判断，不以“用了多少效果”判断。
6. 研究证据与成片审计留在外部工程，不能泄漏进新稿件的 H3 Prompt。
